# 当月入力と前月の繰越

## 入力方法

- 通常入力の「計上日」は、日本時間の毎月1〜5日には前月1日から今日まで、6日以降は当月1日から今日まで。前月分の締め切りは翌月5日23:59:59（日本時間）。未来日・前々月以前は新規登録できない。
- 例: 10月5日までは9月1〜30日の取引を通常入力でき、9月の集計へ反映する。10月6日からは9月の日付を通常入力できないため、「繰越」で10月の精算へ計上する。
- 前月の入力漏れを当月の精算に含める場合は、入力画面の「繰越」を押す。「計上日」は当月の日付、「前月の実際の取引日」は前月1日から前月末日までを指定する。
- 例: 10月15日に9月30日の漏れが判明した場合、計上日を10月15日、繰越の取引日を9月30日にして登録する。9月の集計は変わらず、10月の貸借・精算に含まれる。
- 追加グループにも個別に繰越ボタンがある。同じグループの品目には共通の日付・繰越設定が適用され、通常入力と繰越をグループごとに混在できる。
- 繰越を解除すると元の取引日欄を隠し、通常入力として送信する。入力していた元の日付は、再び繰越を選ぶまで画面内で保持する。
- 2か月以上前の取引を繰越として新規登録する機能は含まない。既存行を選んで取り消す逆取引修正は、従来の修正元照合を維持する。

## 保存と集計

繰越は、貸借表の列数・既存行を変えず、A列に当月の計上日、K列に `↪繰越（前月取引日: YYYY-MM-DD）` を保存する。金額・品目などは通常どおり。L/M列の受付ID・内容ハッシュには繰越フラグと元の取引日も含める。通常入力の既存ハッシュは変更しない。

月次集計・CSV・月次報告はA列の計上日を基準にする。締め切り前の通常入力は指定した前月の集計に入り、繰越は前月へ遡及しない。分析画面の修正欄を「修正・繰越」とし、明細に元の日付を表示する。繰越は `✏️修正` と異なり、相殺対象にしない。借主への既存の登録通知にも繰越と元の日付を記載する。

`js/loan-date-policy.js` と各GASソース末尾の規則は同一内容に保つ（テストで照合）。端末・GASプロジェクトのタイムゾーンに関係なく、日本時間を使う。画面を開いたまま月や5日の締め切りをまたいでも、入力値を消さずに選択範囲を更新し、送信直前とGASのロック内で再検証する。

保存済み受付の照合を日付検証より先に行う。通信断後の月またぎ再送は同じ受付IDで保存結果を確認できるが、未保存行を閉じた月へ追加することはできない。過去日付を再送する画面側の例外も、送信を試みた受付が端末に残る場合だけ。

2026-10-15、本番GASを既存デプロイIDのv83からv84へ更新し、公開GETの `datePolicyVersion: 1` と `receiptColumnsReady: true` を確認。GASの不変v84と検証済み候補の全ファイル一致、manifest・既存サポートファイルが変更されていないことも確認した。公開画面は `main` ブランチからGitHub Pagesへ配信する。

通常テスト260件、実GAS候補を追加した受付・登録テスト134件、5日と6日のスマホ・タブレット・PC計6ケースが成功。本番取引のテスト登録・通知メール送信は行っていない。

1. [受付IDの運用ガイド](DUPLICATE_PREVENTION.md) に従って、実際のGASコードを取得・保存する。参考用 `.gs` による全置換はせず、日付検証・繰越保存・ハッシュ・通知・GETの差分と共通規則を実コードへ適用する。
2. 既存デプロイID・権限を維持してGASを先に反映し、公開GETの `datePolicyVersion: 1` を確認する。新規の過去月登録が制限されるため、切替時刻も確認する。
3. 入力画面・共通JS・分析画面をPagesへ反映し、公開ファイルを照合する。新画面はサーバーの対応版を確認するまで登録を停止する。修正画面は従来のプロトコルのまま利用できる。
4. 利用者にページの再読み込みを案内する。本番の貸借行にテスト取引を入れたり通知メールを送ったりしない。
