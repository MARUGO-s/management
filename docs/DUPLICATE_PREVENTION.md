# 二重登録防止（受付ID方式）

## 状態と目的

2026-09-29、本番GASの既存デプロイを **バージョン70 → 71** に更新。読み取り専用GETで `idempotencyVersion: 1, receiptColumnsReady: true` を確認した。このクライアント版の公開前提は確認済み。リポジトリ内の `.gs` は本番実コードと照合した参考実装であり、今後これだけを編集しても本番GASには反映されない。

本番スクリプトID: `1YehnHnX_AUqTU8aiP21lKVIHKP8n-OjE7PRh36YrlANaLVKifOQ7v5jU`。公開URL・実行者・既存アクセス設定は維持した。本番貸借行のテスト挿入・メール送信・過去データ削除は行っていない。

通常登録・修正登録の各行に一意の受付IDを付ける。同じ受付IDを再送しても、GASは保存済みの結果だけを返し、新しい貸借行・バックアップ・メールを作成しない。通信切断、応答の消失、途中まで成功した複数件送信、再読み込み後の再送を対象とする。

## 利用者向け

- エラー時は入力内容を変更せず、同じブラウザ・同じサイトから再送する。途中まで登録済みの行は増えない。
- 更新後はページを再読み込みする。更新前の開きっぱなしの画面からの登録はサーバーが拒否する。
- 確認済みの内容を再送すると「別の取引として同じ内容をもう一度登録しますか？」と表示する。キャンセルすると既存の受付を確認するだけ。別取引のときのみOKを選ぶ。
- 結果が不明な受付IDは変更しない。先に同じ内容で再送し、登録結果を確認する。
- 保存機能・Web Locksを使えないブラウザでは送信を停止する。保存エラー時にサイトデータを消して再送せず、管理者へ連絡する。
- バックアップやメールのみ失敗した場合は「データは登録済み・再送不要」と表示する。管理者が通知・バックアップを確認する。

## 技術上の保証と限界

- `js/submission-receipts.js` が全行の受付をlocalStorageの1回の書き込みで保存してから送信する。保存容量不足でも、一部の行だけ別IDに変わることを防ぐ。
- 業務項目と修正元の入力日時（なければ元ID/行番号）、同一バッチ内の同内容行の出現番号をキーにする。異なる品目の順序変更には影響されない。
- Web Locksで同じサイト・同じブラウザの複数タブを排他する。
- GASはScriptLock内で受付IDを検索し、データA:Kと受付ID・内容ハッシュL:Mを同じ `setValues` で保存する。確定後に通知を行う。同じIDで異なる内容ならエラーにする。
- L/Mが既存の別用途で使われていれば上書きせず停止する。新規の受付列は非表示にする。既存A:Kの行・修正表示は変更しない。
- 別端末・別ブラウザ・別サイト、サイトデータ削除、内容を変更した再入力は別IDになる。同内容の別取引を時間だけで自動削除する仕組みではない。共有IDなしの手入力重複は保証対象外。
- 受付を残した行を削除したり、L/Mを削除・切り離して並べ替えると再送判定できなくなる。並べ替え・移動はA:Mを一緒に扱う。過去の重複候補は削除しない。
- 保存直後に実行が中断した場合、再送では行は増えないが、未実行のメールやバックアップは自動再実行しない。通知の厳密な配送保証は別途必要。
- 修正元の行番号の陳腐化を完全解決する変更ではない。入力日時は受付の安定性に使い、挿入位置の既存仕様は維持する。

## テスト

```sh
node --test scripts/test_submission_receipts.cjs
```

GAS2種類のモックと実クライアントの登録関数を使い、同ID再送、内容衝突、修正、保存後の応答消失、途中成功・再送、複数タブ、並び替え、保存エラー、意図した別取引を検証する。本番API・メールには接続しない。モック成功は本番デプロイ完了を意味しない。

## ロールバック

画面を送信停止にしたうえで、前のクライアント版と保存したGASデプロイ版の両方を戻す。旧GASだけに戻すと二重登録防止は失われる。受付列L/Mとブラウザの受付履歴は削除しない。復旧中の再送は受付方式復帰後に行う。
