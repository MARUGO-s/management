# 月次の重複候補報告

## 報告仕様

- 毎月1日 **6時台（Asia/Tokyo / JST）**。GAS の時間主導トリガーなので6:00ちょうどではなく、6:00〜7:00のどこかで実行する。
- **前月が主対象**。タイトル・期間・先頭のセクションは前月だけ。重複の疑いが強い／可能性／入力ミスの要確認を分ける。前月に候補がなければ、先頭に「前月：結果／ありませんでした」を表示する。
- **前々月は最後の補足セクションだけ**。追加入力の目安と、現在も検出される未確認候補（高・中・要確認）を表示する。例えば2026年11月1日は10月分が主対象、9月分が補足。8月以前の全履歴や11月分を別途合算しない。
- 対象月は**取引日**で判定する。比較相手を見失わないよう全行で候補を検出してから月で絞る。どれかの行が前月内ならグループ全体を前月に割り当て、補足に重ねて計上しない。複数月をまたぐ候補の参考額はグループ単位であり、前月内の取引総額ではない。
- 補足の「【追加】」「追加の目安」は、**前月1日6:00:00以降の入力日時を含むグループ**。境界時刻を含む固定基準で、前回の実送信・閲覧・確認履歴との差分ではない。遅れて入力された前々月の行も再点検する。
- 確認済み／未処理の状態は保存していない。「未確認候補」は未取消の現在の候補であり、確認済みの正当な別取引も残る場合がある。修正で相殺された行は共通判定ロジックで除外する。
- 金額は **参考候補額**で、重複や損失の確定額ではない。要確認候補には参考候補額を算定しない。確認できた行だけ画面で逆取引修正する。報告処理はシートを読み取るだけで、取引登録・修正・削除はしない。

## 送り先・受け口・個人情報

既存の LINE Report の `mtalk-loan-report` を使う。専用Bot「貸借管理 報告」から、全権管理者との1対1とBotを招待した対象ルームに配信される。送り先の選択は受け口の責任で、GASから宛先や新しいBotを指定しない。

- LINE Report：`hocbnifuactbvmyjraxy`、`/functions/v1/mtalk-loan-report/report`。
- 貸借管理：`mzismgyctulktrihcwfg`。**報告先として混同しない**。
- GASソース：`docs/gas_scripts/monthly_duplicate_report.gs` → GASの `MonthlyDuplicateReport.js`。
- 共通判定：`js/duplicate-check.js` → GASの `DuplicateCheck.js`。
- `LOAN_MTALK_TOKEN` は ScriptProperties のみ（LINE Report側と同じ32文字以上のsecret）。ログやコードに値を書かない。既存のBearerとHMAC-SHA256署名を維持する。
- `LOAN_MTALK_URL` の省略時は上記LINE Reportを使う。上書きがある場合は、別アプリの環境に向いていないことを運用担当が確認する。
- 入力者名は送らない。日付・店舗・品目・参考額・件数だけ。メール・電話番号らしき要点は切り詰め前に除外し、安全な要点だけ200文字までにする。
- 受け口の既存JSON形式（`dedupe_key`, `title`, `subtitle`, `sections`, `note`, `links`, `dry_run`）を維持。最大4セクション・各8項目/5要点・注記300文字で、新しいスキーマは不要。

## 冪等性・確認・有効化

`dedupe_key = loan-duplicate:<前々月>_<前月>` を**旧2か月版と同じまま維持**する。例：2026年11月実行は `loan-duplicate:2026-09_2026-10`。同月の再実行やカード仕様の切替でも、受け口で同一ルームに二重配信しない。既に同じキーで本送信済みなら、新しいレイアウトを再実行しても再配信されない。キーを変えて再送を強制しない。

- `testMonthlyDuplicateReport()`：既存受け口へ **dry_run=true**。カード・宛先の確認だけ（実通知なし）。これはローカルだけの確認ではなく、署名付きネットワーク要求を行う。
- `setupMonthlyDuplicateReport()`：同じハンドラーのトリガーだけを置き換え、毎月1日6時台JSTのトリガーを1つ作り、続いてdry-runを行う。他のトリガーは消さない。dry-run失敗でもトリガー作成済みになり得るため、確認結果とトリガーの両方を確認する。
- `monthlyDuplicateReport()`：本送信（dry_run=false）。失敗は例外にしてGASのトリガー失敗通知で検知する。

**2026-10-13 本番反映済み。** 本番GASの `MonthlyDuplicateReport.js` だけを更新し、HEADと不変スナップショットv82が監査済みソースと一致することを確認。`setupMonthlyDuplicateReport()` を実行し、月次トリガーがHead・毎月1日・午前6〜7時・GMT+09:00で1つだけ存在することを画面で再確認した。他の `onEdit`・`dailyCleanupAndBackup` トリガーは維持。実シートから生成した改善版の署名付きdry-runがHTTP 200 / `ok:true` / `dry_run:true`となり、既存Bot・管理者2名・招待ルームなし・前月主報告と前々月補足のカードを確認した。今回の反映確認では実メッセージを追加送信せず、取引登録・変更・削除もしていない。予約はHEADで動くため、取引登録Webアプリの既存公開配備v81は変更していない。

復旧する場合は、v81の `MonthlyDuplicateReport.js` だけをHEADへ戻す（他ファイル・既存トリガー・ScriptPropertiesは保持）。反映前4ファイルの控えも保存している。次回の予約は2026年11月1日6時台JSTで、10月分を主報告、9月分を補足する。未来の予約実行・到着はまだ未検証。過去の「未配備」記録だけから現在の設定状態を断定しない。

## ローカル検証（本番通知・書込なし）

```sh
node --test scripts/*.cjs
```
