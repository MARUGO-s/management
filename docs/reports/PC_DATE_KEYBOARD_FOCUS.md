# PC計上日のキーボード入力・Tab表示の修正

## 状態と対象

- ローカル実装・検証済み。本番には未公開。公開には利用者の承認が必要。
- 作業元：`27a5b0278e075beab71282f88b8d1fccdea904e9`。ブランチ：`fix/pc-date-keyboard-focus`。
- 前回のスマホ幅で初期1行にする修正（`fix/phone-width-single-row` / `a066b19`）は別件として保持し、この修正には混ぜていない。

## 要望

1. 計上日で10日以降をキーボード入力しても、01や空欄へ戻らない。
2. 初期表示された今日の日付の月・日をクリックし、年を入れ直さず直接変更できる。
3. Tab／Shift+Tabで移動した入力欄・選択行が、画面下の件数・合計・送信バーに隠れない。

## 原因と対応

### 日付

`refreshPostingDate` は日付の `change` ごとに、同じ `min` / `max` を再設定していた。実Chromeで、1文字目の変更による制限属性の再設定がネイティブ日付欄の連続数字入力をリセットすることを、標準入力だけの最小例と本物のフォームの両方で再現した。「11 → 01」「10 → 空欄」、月だけを変更すると空欄になる現象を確認した。

計上日と繰越の実日付は、制限値が実際に変わった場合だけ `min` / `max` を更新する。入力欄の型、日付の値、年/月/日の表示・カレンダー、初期日の設定、当月・前月5日締め・未来日・繰越の業務規則は変えない。締め切り・日替わり・月替わり・繰越切替時は必要な制限を更新する。

### Tab移動と追従バー

ブラウザ標準のスクロールは入力欄が画面内にあるかを考慮するが、stickyバーによる遮蔽は避けない。PC表示の委譲 `focusin` に表示補助を追加した。ブラウザ標準の移動後にバーの実位置を計測し、8pxの余白を保って必要な分だけスクロールする。行全体が収まる場合は行、折返し行が高すぎる場合は入力欄を優先する。

Tabを横取りせず、フォーカスの再設定・値変更・再初期化・行整理は行わない。フォーム外のモーダル、バー自身、通常スマホ表示は対象外。フレーム待ちの間の対象変更・削除・モード切替も確認してから実行する。

- 入力途中の値とDOM、計上日・繰越元日付、貸主借主、単価数量金額。
- 入力検証、ログイン、重複確認、受付ID、既存のGAS送信先・本文・再送経路。
- GAS、Supabase、取引データ、既存の本体checkoutは未変更。
- `pages/js/main.js` の変更は日付制限の再設定を避ける箇所のみ。実際の送信・検証処理は変更しない。
- 読込キャッシュキーを両変更JSで `2026110401` に更新。
